# Build85 设置、同步与主题修复核对

基线：v1.9.0 Build84 / `a6b23358eac2cb419b165b5b7bbf122b05ec3ead`。官方协议对照：`lyswhut/lx-music-mobile` v1.9.0 / `cd37a979a5845f1220b306b374285f5d38329e8d`。

## 原始 Android 认证与 iOS 对齐

| 步骤 | Android v1.9.0 | 本轮 iOS |
|---|---|---|
| 服务发现 | `/hello`验证v4，`/id`读取服务ID | 相同，版本错误不吞掉 |
| 首次配对密钥 | MD5(配对码/密码)十六进制的前16字符，UTF-8后Base64 | 相同算法，SparkMD5纯JS实现，不依赖JSI |
| 配对请求 | AES模式`AES`，实际为ECB带PKCS填充；字段按换行分隔 | 原生异步AES，保留同一线协议 |
| 密钥交换 | RSA 2048，SPKI公钥，PKCS8私钥，OAEP SHA1/MGF1 | 保留已存在的iOS Security实现，不改参数 |
| 保存密钥重连 | 前缀直接拼设备名，服务回复AES加密hello | 相同，持久化成功后返回 |
| WebSocket认证 | `/socket?i=...&t=...`，t是AES加密固定连接消息 | 等待异步AES并检查连接代次，避免旧请求复活 |
| 数据压缩 | `cg_` + gzip的Base64 | pako+纯JS Buffer，保持原格式 |

Android原文件：`src/plugins/sync/client/auth.ts`、`src/plugins/sync/utils.ts`、`android/app/src/main/java/cn/toside/music/mobile/crypto/CryptoModule.java`及`AES.java`。

旧代码有同步桥接导出、JSI摘要、原生计时器和文件压缩的强制依赖。本轮消除这些对同步路径的非必要依赖；并统一Base64版本。截图本身没有堆栈，不能宣称已唯一定位实体设备当时具体哪一个方法缺失。

## 播放状态与弹窗

播放状态使用主题色相与低于荧光强度的饱和度，按合成背景计算文字对比度；不是固定蓝色。支持浅色、深色、彩色及自定义主题，并针对播放器列表卡片独立计算。纯配置背景下以6:1附近为目标、4.8:1为下限；图片背景不等于逐像素可读性证明，仍需实际观感验证。当前行不填充背景、不加粗、不加左竖条。多选和键盘焦点不再混作播放状态。

只有播放器播放列表使用显式`player-playlist`左侧策略。其余按调用方位置；键盘居中、收藏/确认居中、历史地址底部、播放设置/音效底部。后两项原横屏上游曾使用左侧，但用户最新要求只有播放器列表左侧，故使用底部默认位置。

## 验证边界

独立Node HTTP对端验证线协议，原生异步桥接需要Actions模拟器实测；另使用固定官方同步服务和独立桌面协议客户端覆盖双向更改/重连。不是用户192.168.2.125的实际PC、不是全部局域网或实体键盘验证。不以历史Build84结果代替本次构建。
