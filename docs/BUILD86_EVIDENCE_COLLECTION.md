# Build 86 原生截图证据采集与失败排查

此前交付的证据包缺少独立UI截图，不能据测试步骤的success声称取得或逐张验收截图。本轮使用仓库绝对路径、真实Release模拟器应用、54个场景原生JSON和PNG清单，截图不足会阻止Archive。

运行34813894377的两次尝试都在首个MP3流的getPosition超过3000ms时失败；已保存失败JSON、服务日志。此前只有通用HTTP服务器，Range请求没有得到206支持。当前以仅监听回环的Range媒体夹具替换它，验证HEAD、MIME、完整下载、首尾字节范围、416和并发下载；合成信号延长为30秒避免后续音量/暂停测试遇到12秒片尾。此调整是测试对端的完善，尚不能将其写成失败根因已确认。

保持实际时间推进、暂停、音量、缓存、离线及同步断言和3000ms进度查询上限不变，记录进度查询耗时与时间戳；失败时采样模拟器线程。即使原生播放失败也继续采集独立UI证据，最后仍以失败阻止设备打包，不把局部通过算成完整通过。

不修改生产播放、缓存、同步和窗口逻辑；最终交付取决于完整Actions结果和取回的实际产物。


运行34818433312已取得24项在线及11项离线原生检查全部成功的JSON，包括MP3/FLAC真实时间推进和官方同步服务互通。第一次UI捕获返回真实1032×1376竖屏，虽在RNN声明允许横屏，但未发生场景几何旋转，因此横屏门禁正确失败。测试新增仅在模拟器编译的公开UIWindowScene几何请求模块，先请求真实横/竖屏并核对scene与window方向，再挂载生产组件采集。生产设备不编译此模块，不修改应用实际转屏规则。
